# AZFW0017: Hardcoded connection string detected

| | Value |
|-|-|
| **Rule ID** |AZFW0017|
| **Category** |[Usage]|
| **Severity** |Warning|

## Cause

This rule is triggered when a hardcoded connection string is detected in the Connection property of Azure Functions binding attributes.

## Rule description

Hardcoding connection strings directly in the Connection property of binding attributes poses a significant security risk by exposing sensitive credentials (such as account keys, passwords, and access tokens) in source code. These credentials can be accidentally committed to version control systems, shared with unauthorized users, or exposed in build logs.

The analyzer detects common connection string patterns including:
- Azure Storage: `DefaultEndpointsProtocol=`, `AccountName=`, `AccountKey=`
- SQL Server: `Server=`, `Database=`, `User ID=`, `Password=`, `Data Source=`, `Initial Catalog=`
- Service Bus: `Endpoint=`, `SharedAccessKeyName=`, `SharedAccessKey=`, `EntityPath=`
- Generic patterns: `ConnectionString=`, `Trusted_Connection=`, `Encrypt=`

## How to fix violations

Replace hardcoded connection strings with configuration references that point to app settings or environment variables:

**Bad:**
```csharp
[Function("ProcessMessage")]
public void Run([QueueTrigger("myq", 
    Connection = "DefaultEndpointsProtocol=https;AccountName=test;AccountKey=secret")] 
    QueueMessage message)
{
}
```

**Good:**
```csharp
[Function("ProcessMessage")]
public void Run([QueueTrigger("myq", Connection = "MyStorageConnection")] 
    QueueMessage message)
{
}
```

Then define the connection string in your app settings:
- **local.settings.json** (for local development):
```json
{
  "Values": {
    "MyStorageConnection": "DefaultEndpointsProtocol=https;AccountName=test;AccountKey=secret"
  }
}
```

- **Azure App Settings** (for deployed functions):
Set the `MyStorageConnection` setting in your Function App's Application Settings.

## When to suppress warnings

This warning should generally not be suppressed as it represents a security vulnerability. However, it may be acceptable to suppress in the following rare cases:

- Test code where security is not a concern
- Development environments with dummy connection strings
- When using placeholder values that will be replaced during deployment

Use `#pragma warning disable AZFW0017` to suppress the warning for specific instances.
